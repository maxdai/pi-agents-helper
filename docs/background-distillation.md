# 背景提炼规范（操作卡）

> 来源：2026-09-01 讨论「agents-helper 注入 background 应该怎样最有效」
> （4 agents 共识；完整论证见设计文档决策记录）。适用：`/agents-helper`
> 与 `/agents-helper` 第 1 步背景提炼 + 讨论期间增量插话。

## 一、提炼时对照（写入 --background 前过五问）

1. **关联**：与主题有因果支撑或可行域约束吗？（正论据 + 负论据 + 防错约束；
   删掉它结论与可行域都不变 → 不注入）
2. **排重**：AGENTS.md 协议已覆盖 → 不注入
3. **可核查**：事实句；写法"X 已否决（理由 Y）"，不写"不要用 X"；只给事实
   与约束，不给立场结论
4. **克制**（整体核对）：总量 300~600 字、4~8 条、每条 50~100 字；硬上限
   800；超 1000 = 提炼失败信号；超 8 条 = 主题过宽需裁剪
5. **可引用**：条目编号 背景-N + `[事实]/[约束]/[意图]` 标注；关键约束前置；
   关键事实写全（自包含，不依赖跨轮记忆）

## 二、增量（讨论期间 human 插话注入）

- 主动但有门槛：只注入改变讨论基础的信息（否决方案/纠正事实/新增硬约束）
- 同主题多条合并为一条插话（编号 背景-补充 N），不逐条发
- agents 明确指出"背景缺失 X" → 即时补入
- 编号与存量衔接，可精确引用

## 三、审核（用户编辑 background.md 时双问）

1. 这条事实准确吗？
2. 对本次讨论主题有用吗？

备注：与 AGENTS.md 协议重复的条目删除（终检）。

## 四、验证

- 回显检查作诊断信号：[事实] 类无人引用 = 更像失配；[意图] 类无人引用 =
  可能被挑战（正常）；删除判据 = 删掉后产出是否实质变差
- 超 1000 字 / 超 8 条 = 提炼质量反馈信号
