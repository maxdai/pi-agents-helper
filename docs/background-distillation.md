# 背景提炼规范（background 注入规范）

> 来源：2026-09-01 讨论「agents-helper 注入 background 应该怎样最有效」
> （4 agents 共识，讨论目录已清理，结论定案于此）。适用：`/agents-helper`
> 与 `/agents-helper-tmux` 流程第 1 步的背景提炼，及讨论期间增量插话。

## 前提

background 是讨论子 agents 了解主 pi 背景的**唯一通道**（子 agents 禁用
magic-context/aft、无法自行检索）。注入有效性的标准：**信息准、找得到、
用得上**。

## 一、内容层：给事实与约束，不给立场与结论

1. **事实非立场为根基**：只陈述"是什么"（what is true），不陈述"该怎么做"
   （what should we do）。立场性结论（"应该采用 X"）会退化成回声。
2. **写法规则**（存量 background 与增量插话同属信息层，双通道共用）：
   - 约束写"已否决 X（理由 Y）"（可核查的历史事实），不写"不要用 X"（命令式）
   - 用户偏好写"用户偏好 P"（陈述事实），不写"应该 P"（命令式）
3. **内容构成**：正论据（与主题有因果支撑）+ 负论据（可行域约束）+
   防错约束（已否决方案及理由，防重复踩坑）。判据：删掉它结论不变**且**
   可行域不受影响，才不注入。
4. **排除项**：项目百科类条目（删掉后讨论结论不变）；AGENTS.md 协议已
   覆盖的内容（避免重复占用 system prompt 权重——协议里写的是规则本身，
   链路细节如 gen_agent_def 固化、append-system-prompt 注入时机才是背景
   该写的）。

## 二、数量层：克制，信噪比优先

- 推荐 **300~600 字、4~8 条、每条 1~2 句（50~100 字）**；基准约 500 字
- **硬上限 800 字**；**超 1000 字视为提炼失败信号**（混入了无关或立场性内容）
- 条目超 8 条是"主题太宽需裁剪"的报警器，不是注入量天花板
- 条目对齐"可引用单位"：一条 = 一个论据（30 字太碎、100 字以上指向不精确）
- 低于 200 字时 agents 只能靠猜——接受"提炼不出可不传"，不为凑数注入
- 字数服从条目数而非反过来；主题复杂装不下时，拆给 human 插话分批补，
  而非一次性堆长

## 三、结构层：可引用、可定位

1. **条目化编号**（背景-N）：与讨论消息"作者/序号"引用规范同构——agents
   可精确说"回应背景-3"，主 pi 在插话纠正时也能精准指向具体条目
2. **`[事实]/[约束]/[意图]` 显式标注**：标注让回显检查可诊断——[意图] 类
   无人引用可能是被挑战（正常），[事实] 类无人引用才更像失配信号
3. **关键约束前置、按相关度排序**：背景与协议规则等长文共存于 system
   prompt，长文本中部信息易被淹没（lost-in-the-middle）
4. **自包含写全**：每次唤醒注入同一份静态文本（固化进 agent md 后修改需
   重新 gen_agent_def，更新成本高）——关键事实必须在背景里直接写全，不
   依赖跨轮记忆

## 四、机制层：双通道 + 两阶段把关

### 1. 双通道覆盖（存量 + 增量）

- **存量**：background.md 覆盖启动前主 pi 已有的全部相关讨论内容
  （prepare 时刻快照）
- **增量**：讨论期间主 pi 的新认知经 human 插话注入（信息层，不触碰流程
  判定）。不新增"更新背景"机制，两通道职责清晰

### 2. 增量注入四机制

1. **主动但有门槛**：主 pi 产生与主题相关的新认知即推送，不等 agents 暴露
   缺口（agents 不知道自己不知道）；但只注入改变讨论基础的信息（否决方案、
   纠正事实、新增硬约束），未成形想法攒到自然停顿。边界：只覆盖主 pi 侧
   新事实/新约束，不追着主题自然演化播报
2. **批量合并注入**：同一主题的多条新认知合并为一条插话（内含多条
   "背景-补充 N"编号条目），不逐条 --say——插话无成本（不参与判定、配额
   对称），但注意力有成本，合并降低碎片化占用
3. **agent 暴露缺失即补**：agents 明确指出"背景缺失 X"时，主 pi 即时补入
   （最可靠的触发信号）
4. **编号衔接**：增量条目与存量编号衔接（"背景-补充 N"），保证可引用、
   可被回显检查追踪

### 3. 提炼五问（两级）

写入前过五问，分两级执行：

- **条目级**（逐条过）：
  - ① 关联：与主题有因果支撑或可行域约束吗？（正论据/负论据/防错约束）
  - ② 排重：AGENTS.md 协议已覆盖吗？
  - ③ 可核查：是事实句吗？写法是"X 已否决（理由 Y）"而非"不要用 X"吗？
  - ⑤ 可引用：带稳定编号、按相关度排序吗？
- **批次级**（写入前对整体核对一次）：④ 克制——总量落在 300~600 字、
  4~8 条内吗？删掉任何一条，结论或可行域会变吗？

分级原因：④ 是整体量级判据，若按"每条依次过五问"执行会在每条上空转，
总量超限的漏网查不出来。

### 4. 人工审核关口（双问 + 排重备注）

prepare 后用户编辑 background.md 时依次问：
- ① 这条事实准确吗？
- ② 对本次讨论主题有用吗？

另加规范备注：**审核时发现条目与 AGENTS.md 协议重复的，应删除**（协议排重
已在提炼时五问②初检，此处为终检双保险；三问可作可选升级，不设正式问题）。

两阶段关系：**提炼过五问（主 pi 侧），审核过双问（用户侧）**——五问管
"提炼不跑偏"，双问管"审核有抓手"，主题匹配检查从自觉变成制度化检查点。

## 五、验证闭环

1. **存量覆盖**：五问提炼保证 background.md 质量
2. **增量覆盖**：四机制通道保证讨论期间主 pi 新认知不丢
3. **验证覆盖**：
   - **回显检查**作诊断信号而非删除规则：观察 agents 发言是否引用背景
     关键事实——[事实] 类无人引用更像失配，[意图] 类无人引用可能是被
     挑战；无人引用可能是已被内化为共识前提，只作发现线索，不机械删除。
     删除判据回到"删掉后讨论产出是否实质变差"
   - **超 1000 字提炼失败信号**、**条目超 8 主题过宽报警器**，构成提炼
     质量的反馈闭环

## 六、快速对照表

| 维度 | 标准 |
|---|---|
| 内容 | 事实非立场；正论据+负论据+防错约束；排除百科类与协议已覆盖 |
| 数量 | 300~600 字 / 4~8 条 / 每条 50~100 字；硬上限 800；超 1000 = 失败信号 |
| 结构 | 背景-N 编号；[事实]/[约束]/[意图] 标注；关键约束前置；自包含写全 |
| 机制 | 存量 background + 增量插话（主动有门槛/批量合并/暴露即补/编号衔接） |
| 把关 | 提炼过五问（条目级 ①②③⑤ + 批次级 ④），审核过双问（准确？有用？） |
| 验证 | 回显检查诊断信号；1000 字失败信号；8 条报警器 |
